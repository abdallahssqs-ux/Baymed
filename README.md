# BayMed

منصة عربية لطلاب الطب مبنية بـ Next.js 16 وTypeScript، وتعمل على Cloudflare Workers. تحفظ Cloudflare D1 الحسابات والكورسات والطلبات والملاحظات والاختبارات، ويحفظ R2 الملفات بعيدًا عن الوصول العام. تسجيل الكورس طلب مراجعة فقط؛ لا يمنح الوصول إلا المشرف يدويًا بعد التحقق من الدفع خارج المنصة.

## ما يعمل في المنصة

- صفحة رئيسية وكاتالوج يبحث ويصفّي ويعرض بيانات D1، وصفحة عامة لكل كورس ومعاينة مجانية عند نشرها.
- روابط دخول بريدية صالحة لمرة واحدة، جلسات خادم، حساب طالب ولوحة مشرف محمية على الخادم. يُحدد المشرف الأول عبر `ADMIN_EMAIL` بعد إثبات ملكية بريده.
- إدارة الكورسات والأقسام والدروس، ترتيب بالسحب أو الأسهم، مسودات ونشر، صور أغلفة ووسائط خاصة عبر R2، وطلبات تسجيل وحالاتها وصلاحيات قابلة للسحب فورًا.
- واجهة دراسة، ملاحظات خاصة لكل طالب، تقدم مشاهدة، اختبارات تُصحَّح على الخادم، وقفل جلسة دراسة متزامنة واحدة لكل حساب.
- حماية للملفات المدفوعة على مستوى طلبات API، وعلامة مائية وتنبيه للنسخ. لا يمكن منع تصوير الشاشة أو استخراج كل محتوى يعرضه المتصفح بصورة مطلقة.

## التطوير المحلي

يتطلب Node.js 24 وnpm. من مجلد المشروع:

```bash
bash scripts/setup-local.sh
npm run dev:mail           # طرفية أولى: بريد اختباري محلي على 127.0.0.1:8025
npm run dev -- --hostname 127.0.0.1 --port 3000  # طرفية ثانية
```

ينشئ الإعداد `.dev.vars` من المثال إذا كان غير موجود ويطبق ترحيلات D1 محليًا. غيّر `ADMIN_EMAIL` فيه إلى بريد المشرف المحلي. بعد طلب رابط الدخول، تحفظ الرسالة محليًا في `.cache/latest-login-mail.json` بصلاحية قراءة للمالك فقط. لا تستخدم هذا الخادم البريدي في الإنتاج ولا تحفظ رموز الدخول في Git.

للتحقق من حزمة Cloudflare والوظائف المحلية:

```bash
npm run lint -- --quiet
npm run typecheck
npm test
npm run cf:build
npm run db:migrate:local
XDG_CONFIG_HOME=/workspace/.cache/config npm run cf:preview -- --port 8787
npm run test:integration        # طرفية أخرى، بعد بدء المعاينة
```

يبدأ اختبار التكامل خادم بريد اختباري خاصًا به؛ أوقف `npm run dev:mail` قبله. يختبر مسارات التسجيل والمنح والسحب، الملفات المحمية، الاختبارات، خصوصية الملاحظات وقفل الجلسة على قاعدة البيانات المحلية. لا تشغّله على بيانات إنتاج؛ يرفض أي عنوان غير محلي.

## نشر Cloudflare

جهّز في حساب Cloudflare رمز API بصلاحيات تعديل Workers Scripts وD1 وR2، ومعرّف الحساب. ضع `CLOUDFLARE_API_TOKEN` في حقل الأسرار الآمن و`CLOUDFLARE_ACCOUNT_ID` كمتغير للبيئة؛ لا تضعهما في Git. يتطلب تسجيل الدخول البريدي حسابًا لدى مزوّد Resend، ونطاق إرسال موثّقًا لديه، ومفتاح `RESEND_API_KEY` محفوظًا كسر. يجوز إبقاء عنوان الموقع على `workers.dev` مؤقتًا؛ نطاق إرسال البريد شرط مستقل.

1. أنشئ قاعدة D1 باسم `baymed-db` ودلو R2 خاصًا باسم `baymed-media` في حساب Cloudflare المقصود.
2. استبدل معرّف قاعدة البيانات الوهمي في `wrangler.jsonc` بالمعرّف الحقيقي المعروض بعد إنشاء D1. لا تجعل دلو R2 عامًا.
3. طبّق الترحيلات على D1 البعيدة: `npm run db:migrate:remote`.
4. ابنِ وانشر: `npm run cf:build` ثم `npm run cf:deploy`.
5. عيّن متغيرات Worker: `APP_URL` بالعنوان النهائي `https://…workers.dev`، و`ADMIN_EMAIL` ببريد المشرف الحقيقي، و`AUTH_EMAIL_FROM` بعنوان من نطاق Resend الموثّق. عيّن `RESEND_API_KEY` سرًا في Worker. يمكن استخدام `wrangler secret put NAME` لكل متغير؛ أدخل القيم عبر القناة الآمنة فقط.
6. جرّب الصفحة والكورس، وطلب التسجيل، وإرسال رابط الدخول ووصوله، ثم دخول المشرف ومنح صلاحية تجريبية وسحبها. لا تعتبر النشر جاهزًا للطلاب قبل نجاح هذه الخطوات.

أول بريد يثبت ملكيته عبر رابط الدخول ويطابق `ADMIN_EMAIL` ينال دور المشرف. لا توجد كلمة مرور إدارية ثابتة. فصّلنا خطوات الإعداد لأن بيانات الحساب ومزوّد البريد لم تُضف إلى هذه النسخة من المشروع بعد.

## حالة التحقق والتسليم

نجح `npm run lint -- --quiet` و`npm run typecheck` و`npm test` (3 اختبارات) و`npm run cf:build`، وكذلك `npm run test:integration` أمام معاينة Cloudflare المحلية. غطّى اختبار التكامل طلب التسجيل دون منح تلقائي، دخول المشرف والطالب، منح الوصول وسحبه، حماية الملف المدفوع، تصحيح الاختبار على الخادم، خصوصية الملاحظات، قفل جلسة الدراسة، وتشغيل فيديو المعاينة. لم يكتمل التحقق البصري التفاعلي على المتصفحات أو اختبار إرسال البريد الحقيقي.

النشر الكامل على `workers.dev` وفحصه ما زالا معلّقين حتى تُفعّل R2، ثم يتوفر نطاق إرسال موثّق ومفتاح Resend لاستقبال روابط الدخول فعليًا. تفويض Wrangler الحالي مؤقت ومحفوظ خارج المستودع؛ مسودة إعداد بيئة Codex وحدها لا تنشئ موارد Cloudflare ولا تضبط أسرار Worker.

في حساب Cloudflare المرتبط بهذا المشروع، أُنشئت قاعدة `baymed-db` بالمعرّف المسجل في `wrangler.jsonc` وطُبقت عليها الترحيلات الثلاث؛ يوجد فيها كورس تجريبي واحد. نطاق الحساب `baymed.workers.dev` مسجّل. خدمة R2 غير مفعّلة حاليًا في الحساب، وقد رفضت Cloudflare إنشاء `baymed-media` بالرمز `10042` ونشر Worker بالرمز `10085`. يجب تفعيل R2 من لوحة الحساب قبل إعادة النشر. لا ينسخ `npm run cf:deploy` ملف `.dev.vars` المحلي إلى أسرار الإنتاج. عنوان `workers.dev` لا يوفر نطاق إرسال بريد؛ حتى خدمة Cloudflare Email Sending تتطلب نطاقًا مملوكًا ومهيّأً للإرسال.

## الملفات والبنية

- `migrations/`: مخطط D1 والكورس التجريبي الواحد، دون بيانات طلاب أو تقييمات وهمية.
- `src/lib/server/`: المصادقة والصلاحيات والكتالوج والإدارة والوسائط والاختبارات.
- `src/components/`: الواجهة العامة، الدراسة، الإدارة، وعناصر التصميم.
- `tests/`: فحوص أمن وتصحيح وحدات، واختبار تكامل للمعاينة المحلية.
- `.dev.vars.example` و`.env.example`: أسماء الإعدادات المطلوبة دون أسرار حقيقية.

## Ollama لتطوير المشروع

`bash scripts/setup-ollama.sh` يجهز نموذجي `qwen2.5-coder:3b` و`qwen3:4b` محليًا، و`bash scripts/codex-ollama.sh coder` أو `arabic` يفتح Codex الطرفي مع النموذج المختار. هذه أدوات تطوير محلية وليست جزءًا من عامل BayMed المنشور أو قائمة نماذج واجهة Codex السحابية.
